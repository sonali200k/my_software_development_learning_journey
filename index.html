The Four Pillars of Web Markup

Before authoring rich web applications, students must rigorously differentiate syntax containers, document
nodes, serialization tokens, and living memory properties.

PILLAR A                   delimiter syntax

What is a Tag?

A tag is pure lexical markup syntax wrapped in angle brackets (tagname) instructing the HTML parser where content begins and ends. Tags are divided into Container tags (paired with closing tag) and Void tags (standalone elements that do not permit nested children).

        SYNTAX COMPARISON                                              TOKEN LEXING
        !-- Container Tag (Opening & Closing) --
        This is parsed paragraph text.

        !-- Void Elements (No child content permitted) --
        img src="avatar.png" alt="Profile"
        input type="text" name="username"
        br hr meta charset="UTF-8"

PILLAR B                   DOM Node Structure

What is an Element?

An element represents the entire logical entity: the opening tag, all internal character data, child tags, and the closing tag. In the browser memory space, each parsed element converts into an addressable DOM Node instance inheriting from HTMLElement.

        DOCUMENT OBJECT TREE                                             MEMORY NODE
        ┌── [HTMLElement: HTMLAnchorElement] ──────────────┐
        │  Tags:     a href="/lab"> ... a>                 │
        │  Children: [TextNode: "Launch Exercise"]         │
        │  DOM API:  node.textContent, node.href           │
        └──────────────────────────────────────────────────┘

PILLAR C                   key="value" config

What is an Attributet?

Attributes are key-value modifiers written directly inside the opening tag. They configure initial element behaviors, identify DOM nodes (id, class), supply accessibility labels (aria-*), or store custom metadata (data-*).

        DECLARATIVE MARKUP CONFIG                                       ATTRIBUTE SPEC
        !-- Global & Specific Form Field Attributes --
        input 
        type="email" 
        name="student_email" 
        id="usr-email"
        required 
        placeholder="name@school.edu"
        data-checkpoint="field-02"
        />

PILLAR D                   Markup vs Runtime Engine

Attribute vs. DOM Property

Attributes are serialized in HTML text and initialize default states. Properties are live JavaScript object variables in memory. When a user types into an input, input.value (property) mutates continuously, but the serialized attribute remains unchanged unless updated via setAttribute().

        LIVE DESYNCHRONIZATION DEMO                                     DOM RUNTIME
        const el = document.querySelector('input');
        // User types 'alex99' into the field:
        console.log(el.getAttribute('value')); // null or initial 'default'
        console.log(el.value);                // 'alex99' (Live Property)
        // Live Boolean sync: el.checked vs el.hasAttribute('checked')
